# emp-genai

AI-powered employee performance review pipeline.
Extracts text from screenshots and Zoom transcripts, stores embeddings in
pgvector, answers 7 review questions (each with 3 subquestions) in parallel
using a local CPU LLM, and outputs a populated Word document.

---

## Architecture

```
POST /api/v1/run-employee-review
         │
         ▼
 1. OCR screenshots          ← pytesseract
 2. Load Zoom transcript     ← .txt or .json
 3. Merge → save as PDF      ← fpdf2
 4. Chunk text               ← LangChain RecursiveCharacterTextSplitter
 5. Embed chunks (batch)     ← sentence-transformers/all-MiniLM-L6-v2
 6. Insert into pgvector     ← SQLAlchemy ORM + pgvector
 7. Build RAG retriever      ← pgvector cosine search
 8. LangGraph fan-out        ← 7 questions × 3 subquestions = 21 parallel RAG calls
 9. Populate template.docx   ← python-docx (run-level token replacement)
10. Return JSON response
```

## Setup

### 1. Clone and install Python dependencies

```bash
git clone <repo-url>
cd emp-genai
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Set up PostgreSQL

```bash
# Create the database (run as postgres superuser)
psql -U postgres -c "CREATE DATABASE emp_genai;"

# Run the setup script
psql -U postgres -d emp_genai -f db_setup.sql
```

This creates:
- Extension: `vector` (pgvector)
- Schema: `emp_ai`
- Table: `emp_ai.employee` with all required columns
- Indexes: IVFFlat cosine index on `emb`, B-tree on `emp_id`

### 3. Configure environment

```bash
cp .env .env.local   # edit with your values
```

Key variables:

| Variable | Description |
|---|---|
| `DB_URL` | PostgreSQL connection string |
| `MODEL_PATH` | Path to your `.gguf` model file |
| `LLM_THREADS` | CPU threads for llama.cpp (set to your core count) |
| `EMBED_MODEL` | HuggingFace embedding model ID |
| `TEMPLATE_PATH` | Path to `templates/template_answer.docx` |
| `OUTPUT_DIR` | Directory for generated `.docx` files |

### 4. Download a free LLM

```bash
pip install huggingface-hub
huggingface-cli download TheBloke/TinyLlama-1.1B-Chat-v1.0-GGUF \
    --include "tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf" \
    --local-dir models/
```

Other good free CPU models:

| Model | Size | Quality |
|---|---|---|
| TinyLlama 1.1B Q4 | ~700 MB | Fast, basic |
| Phi-2 Q4 | ~1.6 GB | Better reasoning |
| Mistral 7B Q4 | ~4 GB | Best quality |

### 5. Regenerate template (optional)

The template is already included. To regenerate it:

```bash
npm install -g docx
node create_template.js
```

### 6. Start the API

```bash
python run.py
# → Listening on http://0.0.0.0:8000
# → Swagger UI at http://localhost:8000/docs
```

## API Usage

### Run a review

```bash
curl -X POST http://localhost:8000/api/v1/run-employee-review \
  -H "Content-Type: application/json" \
  -d '{
    "emp_id": "EMP-001",
    "screenshot_paths": ["data/screen1.png", "data/screen2.png"],
    "transcript_path":  "data/zoom_transcript.txt"
  }'
```

### Response body (JSON)

```json
{
  "emp_id": "EMP-001",
  "answers": {
    "Q1": {
      "question": "What are the employee's key strengths demonstrated in this session?",
      "sub_answers": [
        { "subquestion": "... — aspect 1", "answer": "Strong communication ..." },
        { "subquestion": "... — aspect 2", "answer": "Consistent delivery ..." },
        { "subquestion": "... — aspect 3", "answer": "Collaborative mindset ..." }
      ],
      "combined_answer": "• ... — aspect 1\n  Strong communication ...\n\n• ..."
    },
    "Q2": { "..." : "..." },
    "...": "..."
  },
  "docx_path": "output/EMP-001_final_answer.docx"
}
```

### Download populated .docx

```bash
curl -O http://localhost:8000/api/v1/download/EMP-001
```

## The 7 Review Questions

| # | Question |
|---|---|
| Q1 | What are the employee's key strengths demonstrated in this session? |
| Q2 | What areas of improvement or development gaps were identified? |
| Q3 | How effectively did the employee communicate and collaborate? |
| Q4 | What specific achievements or contributions did the employee make? |
| Q5 | How did the employee handle challenges or difficult situations? |
| Q6 | What is the overall performance rating and justification? |
| Q7 | What are the recommended next steps or action items? |

Each question is answered by 3 parallel subquestions via RAG, then synthesised into one `combined_answer`. The combined answers populate the `{{Q1_ANSWER}}` … `{{Q7_ANSWER}}` placeholders in `template_answer.docx`.

## Key Design Decisions

**DB session injection** — `get_db()` uses `yield` in a `try/finally` block. FastAPI's `Depends(get_db)` scopes the session to the request and guarantees `close()` / `rollback()` even on errors.

**Singleton services** — the LLM, embedding model, and all stateless services are module-level singletons in `employee_routes.py`. They are instantiated once at import time, not per request. This avoids reloading a multi-GB GGUF file on every call.

**Parallel execution** — `build_and_run_graph()` fires all 7 question coroutines with `asyncio.gather`. Each coroutine fires its 3 subquestion threads with a second `asyncio.gather`. Total: 21 concurrent RAG calls, all using `asyncio.to_thread` because llama.cpp is a blocking C extension.

**Run-level docx replacement** — Word splits tokens like `{{Q1_ANSWER}}` across multiple XML runs when the user edits the template. `TemplateService._replace_in_paragraph()` collapses all runs to a single string before replacing, then writes back to `runs[0]` and clears the rest.
